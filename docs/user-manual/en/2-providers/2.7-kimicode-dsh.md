# 2.7 Kimi Code CLI & DeepSeek Harness

This fork adds first-class support for two more tools, both managed in **switch mode**: you pick a provider and it becomes the tool's default model.

## Kimi Code CLI (`kimicode`)

Moonshot AI's terminal coding agent — the `kimi` command (npm `@moonshot-ai/kimi-code`).

### Configuration Directory

Default: `~/.kimi-code/` (override with the `KIMI_CODE_HOME` environment variable).

### Key Files

```
~/.kimi-code/
├── config.toml       # Providers, models, default_model, thinking, MCP timeouts
├── mcp.json          # User-level MCP servers (mcpServers)
├── AGENTS.md         # System prompt / instructions
├── skills/           # Skills directory
└── sessions/         # Session records
```

### config.toml

CC Switch writes the selected provider into `[providers.<key>]`, declares a matching `[models."<alias>"]`, and sets the top-level `default_model`. The write is **non-destructive**: unrelated tables such as `[thinking]`, `[loop_control]`, and any `/login`-managed (OAuth) providers are preserved.

```toml
default_model = "kimi-code/kimi-for-coding"

[providers.moonshot]
type = "kimi"
base_url = "https://api.moonshot.ai/v1"
api_key = "sk-xxx"

[models."kimi-code/kimi-for-coding"]
provider = "moonshot"
model = "kimi-for-coding"
max_context_size = 262144
```

| Field | Description |
|-------|-------------|
| `providers.<key>.type` | `kimi`, `anthropic`, `openai`, or `openai_responses` |
| `providers.<key>.base_url` | API endpoint |
| `providers.<key>.api_key` | API key (credentials only come from this file) |
| `default_model` | Active model alias |

### MCP

MCP servers are synced to `~/.kimi-code/mcp.json` under `mcpServers` — the same shape as Claude's MCP JSON.

### Skills / Prompts / Sessions

- Skills: `~/.kimi-code/skills/`
- Prompts: `~/.kimi-code/AGENTS.md`
- Sessions: `~/.kimi-code/sessions/` (browsable in the Session Manager; resume with `kimi --session <id>`)

## DeepSeek Harness (`dsh`)

DeepSeek AI's plugin-based agent harness — the `dsh` command (npm `@deepseek-ai/dsh`).

### Configuration Directory

Default: `~/.dsh/` (override with the `DSH_HOME` environment variable).

### Key Files

```
~/.dsh/
├── settings.yaml       # Provider routes + agent-default-model
├── .credentials.yaml   # Credential store (refs.<ENV_NAME>)
├── AGENTS.md           # User-global instructions
├── skills/             # Skills directory
└── sessions/           # Session logs
```

### settings.yaml

CC Switch writes the selected route into `llm-pi-ai.providers.<id>` and points `agent-default-model` at it. Other namespaces (e.g. `web-search-deepseek`) are preserved.

```yaml
llm-pi-ai:
  providers:
    moonshotai:
      displayName: Moonshot AI (Kimi)
      api: openai-completions
      baseURL: https://api.moonshot.ai/v1
      apiKeyEnv: MOONSHOT_API_KEY
      models:
        - id: kimi-k2
          name: Kimi K2
          contextWindow: 262144

agent-default-model:
  provider: moonshotai
  model: kimi-k2
```

| Field | Description |
|-------|-------------|
| `llm-pi-ai.providers.<id>.api` | `openai-completions`, `openai-responses`, or `anthropic-messages` |
| `llm-pi-ai.providers.<id>.baseURL` | API endpoint (optional for built-in catalog ids) |
| `llm-pi-ai.providers.<id>.apiKeyEnv` | Name of the credential reference |
| `agent-default-model` | Active route (`provider` + `model`) |

### Credentials

The API key itself is written to `~/.dsh/.credentials.yaml` under `refs`, keyed by the `apiKeyEnv` name used in `settings.yaml`:

```yaml
version: 1
refs:
  MOONSHOT_API_KEY: sk-xxx
```

### MCP

Deferred. DSH configures MCP through an unstable Cordis patch format (`cordis.patch.yml`); the app is registered but servers are not projected yet.

### Skills / Prompts / Sessions

- Skills: `~/.dsh/skills/`
- Prompts: `~/.dsh/AGENTS.md`
- Sessions: `~/.dsh/sessions/` (JSONL, zstd-aware; browsable in the Session Manager)

## Notes

- Both tools use the shared **provider / MCP / Skills / Prompts / Sessions** panels; enable or hide them under **Settings → Homepage Display**.
- Switching back to the tool's official login is done inside the tool itself (`/login` for Kimi); CC Switch only rewrites the provider route it manages.
